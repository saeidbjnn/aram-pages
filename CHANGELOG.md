# Changelog

All notable changes to ARAM are documented here.

## 3.4.0 — 2026-08-08

### Added

- Optional Capacitor 8 iOS wrapper configuration while preserving the root PWA as the shared application core.
- `js/native-timer-bridge.js` as the only web-to-native timer synchronization boundary.
- Local Swift Package `AramNativeTimer` for ActivityKit, local notifications, native sound preview and restrained haptics.
- Real WidgetKit/ActivityKit Live Activity source for Lock Screen and Dynamic Island compact, minimal and expanded presentations.
- Timestamp-driven native countdown and progress; no per-second JavaScript or ActivityKit update loop.
- Contextual Persian notification permission flow inside the existing timer settings.
- Curated completion sounds: آرام، زنگ نرم، چایم، مینیمال، سیستم and بدون صدا.
- Native-web asset build script and Xcode integration templates.
- Native-timer architecture, Live Activity, notification and timer-test documentation.

### Changed

- Store schema upgraded from 4 to 5 for native timer preferences while preserving all module and productivity records.
- New installations now default Auto Continue to OFF; migrated users keep their explicit previous value.
- Timer lifecycle emits stable Start/Pause/Resume/Stop/Complete transitions to native iOS without emitting ordinary clock ticks.
- PWA Service Worker cache includes the native bridge and local sound assets; Service Worker registration is skipped inside the Capacitor iOS container.
- An expired persisted timer restored after relaunch now emits only the authoritative completion transition, preventing a second idle sync from immediately dismissing completion state.

### Fixed

- Native notification requests use deterministic session IDs so Resume replaces rather than duplicates an alarm.
- Pause and Stop cancel the pending native completion notification.
- Native completion cannot create a second timer engine or duplicate session/statistics records.
- Foreground native completion plays the selected sound directly when notification delivery is unavailable or disabled, while avoiding duplicate sound when an authorized notification owns the completion alert.
- Fractional ISO timestamps generated by JavaScript are parsed correctly by the Swift bridge.
- Custom Focus/Work/Break timers retain the Phase 3.1.1 rule that they never enter preset Auto Continue cycles.

### Removed

- No existing web feature was removed. No fake web Live Activity was added.
- Interactive Live Activity Pause/Resume/Stop controls were intentionally not added because they would introduce a second mutation path before shared native state rules exist.

### Known issues

- Physical-iPhone certification is still required; this environment cannot run Xcode, sign an app or validate real Lock Screen/Dynamic Island behavior.
- After force termination, iOS can deliver the scheduled local notification and the Live Activity can become stale at the expected end date, but a local ActivityKit API cannot guarantee a future `activity.end()` invocation after the process has been killed. ARAM reconciles and ends the activity on the next launch.
- The generated standard Capacitor `ios/` Xcode project must be created on macOS because this environment cannot reach the public npm registry; the repository includes the config, local native package, Widget Extension source and integration checklist rather than a fabricated Xcode project.

## 3.3.0 — 2026-08-07

### Added

- Central module registry with stable IDs, versions, destinations, storage namespaces and capability declarations.
- Optional specialized modules for Reading, University, Screen Time, Work and Projects.
- Personalized More screen with pinned and active modules.
- Module Library with Active, Available, Hidden and Custom groups.
- Module lifecycle controls for activation, hiding, restoration, deactivation, archiving, reactivation, pinning and accessible reordering.
- Optional four-step onboarding for new users with persisted resume and skip support.
- Five generic custom-module templates: Simple Tracker, Project, Routine, List and Time Tracker.
- Concise configurable optional-module summaries on Today.
- Module-aware Search, Calendar, Statistics and reviews.
- Validated JSON import with an automatic pre-import backup.
- Schema-3 migration snapshot and retryable migration-error flow.
- Phase 3.3 architecture, migration, QA and dogfooding documentation.

### Changed

- Store schema upgraded from version 3 to version 4.
- Reading, University and Screen Time are registered specialized modules without changing their existing records or depth.
- Work and Projects are registered facades over existing records rather than duplicate databases.
- Optional Quick Add entries and statistics are shown only for active modules.
- Search results now display their source module and respect hidden-module preference.
- Exported backups include application version, schema version, module configuration, custom definitions and all records.
- Service Worker cache upgraded to include the complete module system.
- New installations start with the universal core rather than every optional lifestyle section.

### Fixed

- Active module cards in More could render without a functioning open action.
- Hidden Reading or University search results could bypass module lifecycle controls.
- Persian digits were rejected by custom Time Tracker numeric fields.
- Permanently deleting University could remove independent Projects facade records.
- Custom List records could incorrectly create calendar activity despite lacking Calendar capability.
- Damaged schema-4 data with records but missing module preferences could be treated as a new installation.
- Work statistics used an irrelevant archived-task count instead of actual occurrence completion.
- Resetting all data did not immediately restart optional onboarding.
- Inactive University and Projects deadlines could still appear in Today upcoming items.
- Onboarding use-case answers could silently activate recommended modules beyond the user’s explicit selection.
- More could show «هنوز بخشی اضافه نکرده‌ای» when every active module was pinned.

### Removed

- Fixed lifestyle-specific cards from the normal More experience when their modules are inactive.
- Inactive optional-module empty statistics from the default Statistics view.

### Known issues

- LocalStorage remains synchronous and rewrites the complete normalized state per mutation.
- Generic deleted-record restoration exists in the command layer but does not yet have a dedicated deleted-record browser in every template.
- Installed-PWA migration, VoiceOver and TalkBack still require physical-device certification.

## 3.1.1 — 2026-08-06

### Changed

- Custom-duration input now uses three fixed fields in visual `HH:MM:SS` order: hour on the left, minute in the middle and second on the right.
- Timer displays durations of one hour or more using `HH:MM:SS`.
- Timer runtime now records whether a duration came from a built-in preset or the custom-duration form.

### Fixed

- A custom timer created while the Work or Break segment was active could incorrectly enter the built-in work/break auto-continue cycle after completion.
- Existing saved custom work/break durations from version 3.1.0 are inferred during normalization when they differ from the saved preset.

### Known issues

- System notifications still require permission granted outside ARAM; in-app feedback, enabled sound and supported vibration remain available.

## 3.1.0 — 2026-08-06

### Added

- Regression coverage for all twelve Phase 3.1 bug reports.
- Jalali-first date controls for every existing date field, with Gregorian dates retained as secondary context.
- Visible task edit actions and horizontal swipe-to-edit support.
- Minute-and-second custom timer input.

### Changed

- Focus-ring rendering now follows real elapsed milliseconds through a requestAnimationFrame visual clock.
- Empty statistics rings now show descriptive empty states instead of unsupported zero percentages.
- Numeric fields normalize Persian, Arabic and English digits to canonical ASCII storage values.
- Modal close controls use one optically centered SVG icon.

### Fixed

- Duplicate top-level page titles.
- Focus-ring timing, jumping, pause/resume continuity and reset behavior.
- Silent timer completion on supported devices.
- Unexpected focus-timer restart after custom completion.
- Long-press text selection outside editable controls.

### Removed

- Native Gregorian-first date-picker presentation from application forms.
- Text-based modal close glyph.

### Known issues

- System notifications still depend on browser permission already being granted; ARAM never requests notification permission in Phase 3.1. In-app announcement, toast, sound and supported haptics remain available.

## 3.0.0 — 2026-08-06

### Added

- Hidden Developer Mode, opened only after five taps on the application version.
- Local error log for JavaScript errors, unhandled promises, storage failures, rendering failures, navigation errors, timer errors and unexpected exceptions.
- Local-only analytics for screen visits, time per screen, button interactions, navigation flows, session duration, task completion, habit completion, reading sessions and focus sessions.
- FPS samples, long-task samples, optional Chromium memory information and storage inspection.
- Exportable debug report containing diagnostics, environment metadata and database metadata.
- Keyboard skip link, bottom-sheet focus trap, focus restoration and background inert handling.
- Automated static accessibility, PWA, storage-pressure, concurrency, random-lifecycle and Service Worker tests.
- Reusable Chromium QA runner at `qa/browser_qa.py`.
- Cross-tab storage synchronization for newer revisions.

### Changed

- Application version updated to 3.0.0.
- Rendering now invalidates views by store revision and renders the active view instead of rebuilding every screen after every mutation.
- Calendar activity and statistics selectors are cached by store revision.
- Timer reconciliation now catches up every fully elapsed work/break interval after a long background suspension.
- Timer polling interval changed from 250 ms to 500 ms while retaining timestamp accuracy.
- Bottom Sheets now use dialog semantics, keyboard containment and deterministic focus behavior.
- Service Worker upgraded to cache version 5 and stale-while-revalidate asset handling.
- Motion durations standardized to 180–280 ms and disabled when reduced motion is requested.
- Interactive targets, form controls and empty states received usability and accessibility safeguards without changing the visual identity.
- Dynamic buttons now declare explicit `button` or `submit` behavior.
- Developer Mode was isolated in `js/developer-mode.js` rather than embedded in the main application module.

### Fixed

- Multiple work/break cycles elapsed in the background were previously reduced to one completed phase.
- A stale browser tab could overwrite a newer LocalStorage revision.
- Storage quota failures could fail without preserving a clear diagnostic trail.
- Diagnostic storage failure did not remain visible in the in-memory error log.
- Generated bar charts used markup not covered by the old CSS selector.
- Large text on narrow screens could overlap the top actions.
- Programmatic main-content focus could display a large page-sized outline.
- Developer panel automatic refresh could reset scroll and focus while logs were being inspected.
- The new diagnostic modules were not part of the previous PWA application shell.
- Implicit button types could accidentally submit a surrounding form after future markup changes.

### Removed

- Unused `readingSessionsInRange` and `createId` imports from `app.js`.
- Unused legacy work-preset card CSS.
- Automatic Developer Mode rerendering that interrupted manual inspection.
- Direct component color literals for charts where semantic ring tokens already existed.

### Known issues

- `app.js` remains large and should be separated by view and sheet in a future architecture phase.
- LocalStorage persistence still clones, normalizes and serializes the complete data model synchronously.
- Cross-tab revision checks prevent stale overwrites, but LocalStorage cannot provide a truly atomic compare-and-swap for two writes beginning at the exact same revision.
- `performance.memory` is browser-specific and is unavailable in Safari and Firefox.
- Real installed-PWA verification on iOS and Android hardware remains required before store submission.
- The execution environment blocked localhost navigation in Chromium, so the Phase 3 Service Worker was verified through executable unit simulation and asset validation rather than an installed localhost session.
